# WK03: เอกสารความต้องการระบบ (Requirements Document)

## ระบบบริหารร้านกาแฟ (Coffee Shop POS & Inventory System)

---

# 1. บทนำ

## 1.1 วัตถุประสงค์

เอกสารฉบับนี้จัดทำขึ้นเพื่อรวบรวมและวิเคราะห์ความต้องการของผู้ใช้งานสำหรับระบบบริหารร้านกาแฟ ซึ่งครอบคลุมการรับออเดอร์ การชำระเงิน การจัดการสต็อก และการติดตามยอดขายของหลายสาขา เพื่อใช้เป็นแนวทางในการออกแบบและพัฒนาระบบในขั้นตอนถัดไป

## 1.2 ผู้มีส่วนได้ส่วนเสีย (Stakeholders)

* เจ้าของร้านกาแฟ
* ผู้จัดการสาขา
* พนักงานแคชเชียร์
* บาริสต้า
* ลูกค้า

---

# 2. ขอบเขตของระบบ (System Scope)

## ระบบสามารถทำได้

* รับคำสั่งซื้อผ่านระบบ POS
* คำนวณราคารวมโดยอัตโนมัติ
* รองรับการชำระเงินทั้งเงินสดและ QR Payment
* ส่งข้อมูลออเดอร์ไปยังหน้าจอบาริสต้า
* อัปเดตสต็อกวัตถุดิบอัตโนมัติ
* แสดงสถานะของออเดอร์
* จัดเก็บประวัติการขาย
* แสดงรายงานยอดขายของแต่ละสาขา
* ตรวจสอบสต็อกของทุกสาขา
* จัดการข้อมูลเมนูเครื่องดื่ม

## ระบบไม่ครอบคลุม

* ระบบบัญชีและภาษี
* ระบบเงินเดือนพนักงาน
* ระบบจัดซื้อวัตถุดิบจากซัพพลายเออร์
* ระบบสมาชิกและการสะสมแต้ม

---

# 3. สรุปผลการสัมภาษณ์

**ผู้ให้สัมภาษณ์:** เจ้าของร้านกาแฟ

| คำถาม                       | คำตอบ                                                   |
| --------------------------- | ------------------------------------------------------- |
| ปัญหาที่พบในการทำงานคืออะไร | ช่วงลูกค้าเยอะ พนักงานจดออเดอร์ผิด และลืมเพิ่มเมนูพิเศษ |
| ต้องการให้ระบบช่วยอะไร      | ลดเวลาการรับออเดอร์และลดข้อผิดพลาด                      |
| ข้อมูลใดที่อยากตรวจสอบได้   | ยอดขาย สต็อก และเมนูขายดี                               |
| รูปแบบการชำระเงิน           | เงินสด และ QR Payment                                   |
| ต้องการใช้งานกี่สาขา        | ประมาณ 3–5 สาขา                                         |
| ใครใช้งานระบบ               | เจ้าของร้าน ผู้จัดการ แคชเชียร์ และบาริสต้า             |
| มีข้อจำกัดอะไร              | ต้องใช้อุปกรณ์ POS เดิมของร้าน                          |
| ต้องการให้เสร็จเมื่อไร      | ภายในภาคการศึกษานี้ (16 สัปดาห์)                        |

# 4. Functional Requirements

| รหัส  | รายละเอียด                                                                |
| ----- | ------------------------------------------------------------------------- |
| FR-01 | ระบบต้องสามารถบันทึกคำสั่งซื้อของลูกค้าผ่านเครื่อง POS ได้                |
| FR-02 | ระบบต้องสามารถคำนวณราคารวม ส่วนลด และยอดชำระโดยอัตโนมัติ                  |
| FR-03 | ระบบต้องรองรับการชำระเงินด้วยเงินสดและ QR Payment                         |
| FR-04 | ระบบต้องส่งข้อมูลออเดอร์ไปยังหน้าจอของบาริสต้าทันทีหลังการชำระเงิน        |
| FR-05 | ระบบต้องสามารถอัปเดตจำนวนวัตถุดิบในสต็อกอัตโนมัติเมื่อมีการขายสินค้า      |
| FR-06 | ระบบต้องสามารถแสดงสถานะของออเดอร์ เช่น กำลังทำ เสร็จแล้ว และรับสินค้าแล้ว |
| FR-07 | ระบบต้องสามารถค้นหาประวัติการขายย้อนหลังตามวันที่ได้                      |
| FR-08 | ระบบต้องสามารถแสดงรายงานยอดขายแยกตามแต่ละสาขาได้                          |
| FR-09 | ระบบต้องให้เจ้าของร้านตรวจสอบข้อมูลสต็อกของทุกสาขาผ่าน Dashboard ได้      |
| FR-10 | ระบบต้องสามารถเพิ่ม แก้ไข และลบข้อมูลเมนูเครื่องดื่มได้                   |

---

# 5. Non-functional Requirements

| รหัส   | ประเภท          | รายละเอียด                                                                           |
| ------ | --------------- | ------------------------------------------------------------------------------------ |
| NFR-01 | Performance     | ระบบต้องตอบสนองการบันทึกออเดอร์ภายในเวลาไม่เกิน 2 วินาที                             |
| NFR-02 | Usability       | พนักงานใหม่ต้องสามารถเรียนรู้การใช้งานระบบและบันทึกออเดอร์ได้ภายใน 30 นาทีหลังการสอน |
| NFR-03 | Reliability     | ระบบต้องพร้อมใช้งานไม่น้อยกว่า 99% ของเวลาทำการ                                      |
| NFR-04 | Security        | ผู้ใช้แต่ละประเภทต้องเข้าสู่ระบบด้วยบัญชีของตนเอง และเข้าถึงเฉพาะเมนูที่ได้รับสิทธิ์ |
| NFR-05 | Compatibility   | ระบบต้องรองรับการใช้งานพร้อมกันอย่างน้อย 5 สาขา                                      |
| NFR-06 | Maintainability | ผู้ดูแลระบบต้องสามารถเพิ่มเมนูและสาขาใหม่ได้โดยไม่ต้องแก้ไขโปรแกรม                   |

---

# 6. ข้อจำกัดของระบบ (Constraints)

* ใช้อุปกรณ์ POS และเครื่องพิมพ์ใบเสร็จที่ร้านมีอยู่
* งบประมาณในการติดตั้งไม่เกิน 30,000 บาทต่อสาขา
* ระบบต้องรองรับร้านกาแฟจำนวน 3–5 สาขา
* ระบบต้องพัฒนาให้เสร็จภายใน 16 สัปดาห์
* ระบบต้องสามารถเชื่อมต่ออินเทอร์เน็ตเพื่อซิงโครไนซ์ข้อมูลระหว่างสาขา

---

# 7. สรุป

จากการสัมภาษณ์เจ้าของร้าน พบว่าปัญหาหลักคือการรับออเดอร์ด้วยวิธีเดิมทำให้เกิดความล่าช้าและความผิดพลาด รวมถึงการตรวจสอบสต็อกและยอดขายทำได้ไม่สะดวก ดังนั้นจึงมีการพัฒนาระบบบริหารร้านกาแฟที่สามารถรับออเดอร์ผ่าน POS จัดการสต็อกแบบอัตโนมัติ และแสดงรายงานยอดขายของทุกสาขาแบบเรียลไทม์ เพื่อช่วยเพิ่มประสิทธิภาพในการดำเนินงานและลดข้อผิดพลาดในการให้บริการลูกค้า
